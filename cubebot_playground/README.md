# CubeBot Playground

Среды CubeBot для MuJoCo: исходная задача balance и отдельная CPU-задача
вставания `cubebot_playground.cubebot.standup`.

## Установка задачи вставания

Из корня репозитория:

```bash
python3 -m venv .venv-standup
.venv-standup/bin/python -m pip install -e './cubebot_playground[standup]' pytest
```

Физика параллельно выполняется через [kevinzakka/mjbatch](https://github.com/kevinzakka/mjbatch),
commit `77966f85bcd8f7ef4351cb4a1a6f42e133d19725`, MuJoCo 3.11.0.
PPO реализован на PyTorch. Отдельное окружение сохраняет зависимости старой
задачи balance; JAX/MJX для вставания не используются.

## Запуск

```bash
.venv-standup/bin/python -m cubebot_playground.cubebot.standup.train \
  --slope-roll 15 --slope-pitch 15 --output checkpoints/standup/horizontal.pt
```

Все четыре ступни изначально находятся в воздухе на 5 мм над опорой,
корпус лежит. Ноги одновременно ставятся на поверхность за 1 секунду,
затем 0.4 секунды отведены на приземление. По умолчанию: 256 сред,
`--num-threads 0` (mjbatch выбирает все логические CPU), 1000 обновлений PPO,
rollout 128, 4 эпохи оптимизации. Бюджет — 32 768 000 шагов среды;
`--updates 500` уменьшает его до 16 384 000. Шаги отдельных оценок в счётчик
обучения не входят. Увеличение числа сред не увеличивает число физических ядер.
Новые параметры применяются только после перезапуска процесса.

Просмотр на macOS:

```bash
.venv-standup/bin/mjpython -m cubebot_playground.cubebot.standup.play \
  checkpoints/standup/horizontal.pt --viewer
```

Headless-проверка:

```bash
.venv-standup/bin/python -m cubebot_playground.cubebot.standup.play \
  checkpoints/standup/horizontal.pt --episodes 10
```

На Linux для просмотра используйте `python ... --viewer` при доступном дисплее.

## ONNX на Raspberry Pi 5

Экспорт на компьютере обучения:

```bash
.venv-standup/bin/python -m pip install -e './cubebot_playground[onnx]'
.venv-standup/bin/cubebot-export-onnx \
  checkpoints/standup/no-yaw.pt checkpoints/standup/no-yaw.onnx
```

Один ONNX-файл содержит сеть, начальную позу, начальную постановку ног, порядок
суставов и ограничения команд. На Raspberry Pi нужны только NumPy и CPU-версия
ONNX Runtime:

```bash
python3 -m venv .venv-onnx
.venv-onnx/bin/python -m pip install numpy onnxruntime
.venv-onnx/bin/python -m pip install -e ./cubebot_playground
```

Runtime принимает roll/pitch каждые 20 мс и возвращает 12 положений приводов:

```bash
printf '%s\n' '{"roll":1.2,"pitch":-2.5}' | \
  .venv-onnx/bin/cubebot-run-onnx checkpoints/standup/no-yaw.onnx \
  --input-degrees
```

Для перезапуска процесса без повторения начальной фазы сохраняйте состояние в
RAM-файле Raspberry Pi:

```bash
.venv-onnx/bin/cubebot-run-onnx checkpoints/standup/no-yaw.onnx \
  --input-degrees --state-file /dev/shm/cubebot-state.json
```

После остановки процесса запустите ту же модель с восстановлением:

```bash
.venv-onnx/bin/cubebot-run-onnx checkpoints/standup/no-yaw.onnx \
  --input-degrees --state-file /dev/shm/cubebot-state.json --resume
```

Файл содержит последние 12 команд, скорость изменения команд и номер фазы.
`/dev/shm` хранится в RAM и не изнашивает SD-карту; после перезагрузки Raspberry
Pi он очищается.

При прямом вызове ONNX вход `observation` имеет `float32`-форму `(1, 14)`:
`[roll/π, pitch/π, command_0/π, ..., command_11/π]`. Выход `normalized_velocity` имеет
форму `(1, 12)` и содержит нормализованные требуемые скорости. Готовый
`cubebot-run-onnx` сам хранит последние команды, применяет ограничения и выдаёт
`positions_rad` и `positions_deg`. Yaw не читается.

## Схема обучения: базовый подъём и обучаемые поправки

Прежняя схема обучала все 12 скоростей напрямую и после supervised warm start
могла потерять подъём. Новая схема сохраняет проверенный контроллер:

```text
базовая скорость = (стоячая IK-поза − предыдущая команда) × коэффициент сближения
поправка PPO = 0.05 рад/с × tanh(выход политики)
команда скорости = базовая скорость + поправка PPO
```

Коэффициент сближения по умолчанию — 1.5/с (`--rise-gain`). Это ускоряет
подъём без изменения пределов скорости, ускорения или момента сервоприводов.
Геометрическая опорная поза приводов рассчитана
на 3 мм выше опорной высоты для компенсации отклонения под нагрузкой.
Опорная высота `--height` по умолчанию 8 см, но точное попадание в неё
не является условием успеха. Ступни базовой позы смещены внутрь на 20 мм
при разрешённом максимуме 30 мм, оставляя запас для выравнивания.
Коэффициент и вся конфигурация сохраняются в checkpoint.

Это residual RL: начало подъёма задано контроллером, политика обучает небольшие
поправки, а не открывает движение с нуля. `--residual-scale` задаёт максимальную
поправку в рад/с (по умолчанию 0.05); меньшее значение ослабляет обучаемую
коррекцию. Нулевой выход сети точно воспроизводит
проверочный подъём. Предварительное supervised-обучение больше не требуется;
старый аргумент `--warm-start-updates` удалён.

После начала подъёма базовый контроллер добавляет коррекцию по мировым
roll/pitch гироскопа, дифференциально меняя разгибание ног. Матрица коррекции
рассчитана из геометрии номинальной стойки. Она не использует истинный угол
плоскости или энкодеры. Коррекция плавно включается по прогрессу предыдущих
команд, ограничена и сохраняется в checkpoint вместе с исходной позой.
Политика учит небольшие добавочные поправки к этому контроллеру.

Для актёра установлен меньший learning rate 3e-5, для критика — 3e-4.
Градиенты актёра и критика ограничиваются отдельно. KL-порог останавливает
слишком большое изменение актёра за обновление; регуляризация удерживает
поправки небольшими. В заданной подготовительной фазе актёр не обновляется.

Главная награда — мировой горизонтальный корпус после подъёма (вес 3).
Точная высота — слабая добавка (вес 0.2). Основная награда плавно включается
между лежачей высотой и минимальной высотой стойки, чтобы лежание не приносило
награду за горизонтальность. Устойчивое стояние получает дополнительный бонус.

После подготовки ступня может сместиться до `--foot-inward 0.03` м в любую
сторону, которая приближает её к номинальному центру корпуса. Это область,
а не линия: ограничиваются полный путь смещения от опоры и уход наружу.
Выход за область с допуском 5 мм штрафуется; штраф продолжает расти линейно
после квадратичного участка. Для успеха все ступни должны оставаться в области
с этим допуском. Уход за область больше чем на 4 см завершает эпизод.
Физическое скольжение по-прежнему штрафуется отдельно: разрешение перестановки
не означает отключения трения.

## Как читать логи и checkpoints

- `prep:` — только подготовительные шаги; малая высота корпуса здесь нормальна.
- `rise:` — только подъём и удержание: средние награда, высота, скольжение и
  смещение ступней. Среднее включает сам подъём, поэтому ниже конечной высоты.
- `episode_success` — успех в последних 256 завершённых учебных эпизодах со
  случайными поправками. До первого завершения выводится `nan`.
- `eval ... success` — доля успешных полных эпизодов без случайных действий;
  по умолчанию оценка проводится на 9 средах каждые 10 обновлений, а также
  до первого обновления. Настройки: `--eval-every`, `--eval-envs`.
- `eval ... tilt_deg` — средний максимальный абсолютный roll/pitch корпуса
  относительно мира в конце эпизода. `level_fraction` — доля эпизодов с наклоном
  меньше 0.12 рад; это не полный успех стойки.
- `eval ... height` — высота в конце эпизода; `rise_slip` и `drift` — средние
  только по подъёму; `stable_tail` — доля устойчивых шагов в последней секунде.

Оценка использует фиксированный seed и сетку из девяти сочетаний конечных наклонов:
roll и pitch принимают отрицательный предел, ноль и положительный предел.
Каждая динамическая оценка начинает с горизонтальной плоскости и лежачего
положения, включает одновременную постановку ног, подъём и изменение наклона.
При `--eval-envs` меньше 9 проверяется только часть сетки; стандартные 9
проверяют все крайние сочетания и центр. В checkpoint записываются результаты
каждого наклона (`evaluation.cases`). Учебные среды используют независимые
равномерно случайные начальные и конечные наклоны при каждом reset и шум ориентации.
Оценка не меняет их состояние. Успех в симуляции не гарантирует работу на
неизвестных материалах, при толчках и аппаратных ошибках.

Путь `--output` содержит **лучший** проверенный checkpoint: сначала сравнивается
успех, затем устойчивость последней секунды, затем скольжение. Последняя политика
сохраняется рядом с суффиксом `.last.pt`. Исходный контроллер тоже проверяется и
сохраняется на update=0. Если он лучше результатов PPO, лучший файл останется
исходным — `update` и `evaluation` внутри checkpoint показывают это явно.

Checkpoint версии 2 содержит веса, стоячую опорную позу, масштаб поправок,
параметры среды и результаты оценки. При запуске на оборудовании нужно переносить
весь контроллер, а не только нейросеть. Файлы не содержат полного состояния
возобновления оптимизатора. Старые checkpoint поддерживаются для просмотра
через прежнее преобразование действий; для новой схемы начните новый прогон
и используйте отдельное имя файла.

## Физическая постановка

Пол — плоскость через мировое начало координат с независимыми наклонами roll/pitch. Корпус лежит на нижнем коллизионном боксе:
начальная высота начала координат корпуса над плоскостью по нормали 0.0224 м. Все ноги согнуты, сферы
ступней радиусом 0.008 м находятся на 5 мм над плоскостью (их центры на 13 мм). IK проверяет достижимость поз и отсутствие
проникновений. Общая модель `cubebot.xml` задаёт массу **800 г** через
`compiler settotalmass="0.8"`; массы частей и инерции масштабируются пропорционально.

Опорная высота `--height` по умолчанию 0.08 м до начала координат корпуса.
Успех не требует точного совпадения с ней: минимальная высота корпуса по нормали
к плоскости — `--min-standing-height 0.045` м. Робот может присесть для выравнивания. Диапазон проверки
0.04–0.085 м, а достижимость с текущей постановкой ног и запасом для приводов
дополнительно проверяется IK; некоторые значения у верхнего предела недостижимы. Для каждой высоты обучается отдельная политика.
Момент приводов — **0.34 Н·м**, регулируется `--torque`.

Актёр и критик получают ровно **14 наблюдений**:

1. Roll и pitch в радианах, делённые на π (WT901-подобная ориентация с шумом
   0.002 рад; протокол датчика и калибровка осей не реализованы).
2. 12 предыдущих отправленных положений приводов в радианах, делённых на π.
   Порядок: `revolute_10, 12, 3, 5, 6, 4, 7, 8, 1, 9, 11, 2`.

Измеренные положения суставов, высота, скорости и контакты не входят в
наблюдения или базовый контроллер; они используются только для награды,
завершения и диагностики. Контроллер имеет собственную историю команд.

Управление 50 Гц, физика 1000 Гц. Шаг физики 1 мс устраняет наблюдавшуюся
на крутых сочетаниях наклонов численную дрожь контактов при 2 мс. Предел скорости команды 60°/с, изменения
скорости 4 рад/с², setpoint интерполируется на физических подшагах.
Команды ограничены областью между исходной, подготовительными и стоячей позами
с запасом 0.8 рад в новой задаче выравнивания, внутри механических пределов.
Прежнее окно 0.08 рад мешало разному разгибанию ног на уклоне. На границе применяется жёсткое
ограничение положения. Плавность физического движения также зависит от контактов
и приводов; сходство с животным оценивается визуально, демонстраций животных нет.

Успех: высота по нормали к плоскости не ниже 4.5 см, мировой roll/pitch
корпуса <0.12 рад, ступни в разрешённой области, четыре ступни у пола,
скорость каждой ступни по XY <0.02 м/с и малая скорость корпуса непрерывно
последние 0.5 с. Эпизод продолжает учить удержание до тайм-аута. Контакт для
награды оценивается по высоте сферы с допуском 1 мм. Падение и тайм-аут различаются
при bootstrap PPO; низкая начальная поза не считается падением.

## Трение, наклоны и одновременная постановка ног

Явные пары «ступня–пол» имеют коэффициент скольжения **μ=1.5** в обоих
касательных направлениях, настраивается через `--friction`.
`condim=4` включает скольжение и вращение вокруг нормали (0.02 м), качение не
включено. `solref="0.01 1"`, `solimp="0.9 0.95 0.001"`, эллиптический конус,
5 итераций noslip. Трение остальных частей — 1.2.
Это параметры симуляции, не измеренные свойства конкретного материала.
Физическое трение не фиксирует ступни и не гарантирует нулевое скольжение.
См. [MuJoCo contact/pair](https://mujoco.readthedocs.io/en/stable/XMLreference.html#contact-pair).

Начальные и конечные roll/pitch плоскости при каждом reset независимо выбираются
из ±15°. Через 2.5 с после постановки ног опора начинает плавно переходить к
новому наклону за 4 с. Параметры: `--slope-change-start` и
`--slope-change-duration`; `--static-slope` отключает изменение после подъёма.
Пределы задаются `--slope-roll` и `--slope-pitch` (0..15°); оба нуля дают
горизонтальную поверхность. Yaw плоскости равен нулю. При одновременных
roll=15° и pitch=15° общий угол нормали к вертикали примерно 21°.
Гравитация остаётся мировой `[0, 0, -9.81]`; наклоняется именно опора, а
исходный корпус ориентируется вдоль неё. У каждой среды собственная ориентация
плоскости, частичный reset не изменяет соседние среды.

Высота, дрейф и скольжение ступней вычисляются в системе плоскости.
Наклон корпуса для награды и успеха вычисляется относительно мирового горизонта.
Ориентация в наблюдениях политики остаётся мировой,
WT901-подобной. Истинный угол плоскости не добавляется во входы политики.
Корпус стремится к мировой горизонтали независимо от наклона поверхности.

Все ноги движутся одновременно из воздушной позы к опоре, с малым перемещением
наружу на 3 мм по каждой горизонтальной оси поверхности. Вся подготовка — 1.4 с,
подъём и удержание — ещё 8 с: полный эпизод 9.4 с / 470 шагов управления.
Подготовительный контроллер игнорирует действия политики и двигает приводы;
позиции ступней не фиксируются принудительно. Счётчик фазы внутренний и не
добавляется во входы. После подготовки конечные точки становятся опорами
для штрафа за боковое смещение; мягкий коридор — 5 мм.

Флаг `--prestep` сохранён как совместимый псевдоним нового запуска: он не
включает прежнее последовательное подшагивание. Старые checkpoint при просмотре
сохраняют свою исходную схему, физический шаг и горизонтальный пол.
Для новой задачи нужно новое обучение.

Просмотр определённого наклона:

```bash
.venv-standup/bin/mjpython -m cubebot_playground.cubebot.standup.play \
  checkpoints/standup/horizontal.pt --viewer --roll 15 --pitch -15
```

Просмотр изменения горизонтальной опоры после подъёма до roll=15°, pitch=-15°:

```bash
.venv-standup/bin/mjpython -m cubebot_playground.cubebot.standup.play \
  checkpoints/standup/horizontal.pt --viewer --roll 0 --pitch 0 \
  --target-roll 15 --target-pitch -15
```

Без `--roll` / `--pitch` при просмотре наклон выбирается случайно для каждого
эпизода. Заданные углы ограничены ±15° и отражаются в реальной геометрии viewer.

## Проверки

```bash
.venv-standup/bin/python -m pytest -q cubebot_playground/tests/test_standup.py
.venv-standup/bin/python -m cubebot_playground.cubebot.standup.train \
  --num-envs 4 --num-threads 2 --updates 2 --rollout 320 \
  --epochs 1 --eval-envs 2 --output /tmp/cubebot-residual-smoke.pt
```

Тесты проверяют физическое трение контактов, массу, начальную геометрию,
одновременную постановку ног и подъём на девяти наклонах, частичные сбросы, отсутствие данных энкодеров во входах,
границы поправок, сохранение/загрузку контроллера и оценку исходного подъёма.

## Проверка горизонтальной стойки

После изменения задачи успехи старой политики, державшей корпус параллельно
склону, не подтверждают горизонтальную стойку. Новый проверочный прогон
использует мировые углы и ослабленную цель высоты. В коротком прогоне на 32 средах
проверка крайних наклонов даёт средний остаточный наклон около 4.4°, все девять
случаев проходят угловой порог. Полный критерий стойки проходит 7 из 9 случаев:
в нём также проверяются контакты, область перемещения ступней и неподвижность.
Это улучшение горизонтальности, а не гарантия идеального выравнивания на любом
уклоне. Новый локальный checkpoint: `checkpoints/standup/horizontal_verified.pt`.

При ограниченных диапазонах суставов и перемещении ступней до 30 мм часть
крутых сочетаний roll/pitch требует компромисса по высоте. Именно поэтому
узкий допуск вокруг 8 см удалён из критерия успеха. Лежачая поза по-прежнему
не считается успешной. После изменения задачи начните новый прогон.
